# Mode-Specific Images

**Date:** 2026-04-19  
**Status:** Approved

## Problem

Blades with multiple modes (e.g. Lightning L-Drago Upper Type / Rapid-Hit Type) have one shared image. When the user toggles modes via `ModeToggle`, the image shown in `PartSelector` does not change to reflect the active mode.

## Goal

When a blade has per-mode images defined, the image shown in `PartSelector` — both the selected-value display and the matching option row in the open dropdown — updates when the active mode changes.

## Data

Add an optional `image` field to each object in a blade's `modes` array in `parts-overrides.json`:

```json
"LIGHTNING L-DRAGO": {
  "name": "Lightning L-Drago",
  "image": "Lightning L-Drago 1-60F (Upper Type).jpeg",
  "modes": [
    { "label": "Upper Type", "image": "Lightning L-Drago 1-60F (Upper Type).jpeg" },
    { "label": "Rapid-Hit Type", "image": "Lightning L-Drago 1-60F (Rapid-Hit Type).jpeg" }
  ]
}
```

- `generate_parts.py` serializes the `modes` array as-is — no script changes needed.
- The top-level `image` field remains as the fallback for blades with no mode images.
- `image` on a mode object is optional; missing entries fall back to `db.image`.

## Image Resolution

Add `getEffectiveImage(partName, modeIndex)` as a local helper in `PartSelector.jsx`:

```js
function getEffectiveImage(partName, modeIndex = 0) {
  const db = BEYBLADE_DB[partName];
  if (!db) return null;
  if (db.modes && modeIndex > 0) return db.modes[modeIndex - 1]?.image || db.image;
  if (db.modes) return db.modes[0]?.image || db.image;
  return db.image;
}
```

This mirrors `getStats` exactly: mode 0 → `modes[0]`, mode N → `modes[N-1]`.

## Component Changes

### `PartSelector.jsx`

- Accept new optional prop `modeIndex` (default `0`).
- In `formatOptionLabel`: for the option whose `value` matches the selector's current `value` prop, use `getEffectiveImage(option.value, modeIndex)` for both `"menu"` (dropdown list) and `"value"` (control display) contexts. All other options continue to use `db.image`.

### `App.jsx`

Wire existing mode state into the blade/assist-blade/bit `PartSelector` calls:

```jsx
<PartSelector label="Blade" ... modeIndex={beyblades[index]?.bladeMode ?? 0} />
<PartSelector label="Assist Blade" ... modeIndex={beyblades[index]?.assistBladeMode ?? 0} />
<PartSelector label="Bit" ... modeIndex={beyblades[index]?.bitMode ?? 0} />
```

No new state is required — `bladeMode`, `assistBladeMode`, and `bitMode` already exist on each `beyblades` entry.

## Files Changed

| File | Change |
|------|--------|
| `src/data/parts-overrides.json` | Add `image` to each mode object for `LIGHTNING L-DRAGO` |
| `src/data/beyparts.js` | Regenerated by `generate_parts.py` |
| `src/PartSelector.jsx` | Add `modeIndex` prop + `getEffectiveImage` helper |
| `src/App.jsx` | Wire `modeIndex` to blade/assist-blade/bit selectors |

## Out of Scope

- `generate_parts.py` — no changes
- `constants.js` / `getStats` — no changes
- `ModeToggle.jsx`, `Beyblade.jsx` — no changes
- URL/share encoding — no changes (mode index already encoded)
- Other parts (ratchets, bits, lock chips) — `image` on mode objects is simply ignored if present
